# กฎการเขียนเนื้อหา (content/)

ใช้เมื่อสร้างหรือแก้ไฟล์ใน `content/` ส่วนรูปแบบไฟล์ดูได้ที่ `docs/SPEC.md` หัวข้อ 7–8

## ผู้เรียนของเรา
- คนทำงานอายุประมาณ 25–45 ปีที่ไม่เคยเขียนโปรแกรม มีเวลาน้อย เรียนได้ครั้งละ 10–15 นาที และมักเรียนตอนเย็นหลังเลิกงาน
- เชี่ยวชาญงานของตัวเองอยู่แล้ว เช่น งานขาย บัญชี HR หรือการตลาด จึงควรยกตัวอย่างจากงานออฟฟิศ
- อาจกลัวคณิตศาสตร์ หรือกลัวว่าตัวเองอายุมากเกินไปที่จะเริ่ม ให้กำลังใจได้ แต่อย่าชมเกินจริง

## น้ำเสียงและภาษา
- เป็นกันเองและสุภาพ เรียกผู้เรียนว่า "คุณ" และไม่ใช้คำลงท้าย "ครับ/ค่ะ"
- เขียนประโยคสั้น ย่อหน้าละไม่เกิน 3–4 บรรทัด
- อธิบายแนวคิดก่อน แล้วจึงบอกชื่อศัพท์
- เปรียบเทียบกับของในชีวิตจริง เช่น ตัวแปรเหมือนกล่องที่มีป้ายชื่อ
- ห้ามใช้คำว่า "ง่ายมาก" "แค่..." หรือ "ใคร ๆ ก็ทำได้"
- ห้ามมีเนื้อหาเกี่ยวกับการเมือง ศาสนา สถาบัน การพนัน หรือข้อมูลของบุคคลจริง
- สะกดตามราชบัณฑิตยสภา: ฟังก์ชัน, แอปพลิเคชัน, อัปเดต, อัปโหลด, ดาวน์โหลด, คอลัมน์, เซิร์ฟเวอร์, เว็บไซต์, อีเมล, ไฟล์

## ศัพท์เทคนิค
- ใช้คำแปลตาม `content/glossary.yaml` เท่านั้น ถ้าศัพท์ยังไม่มีใน glossary ให้เพิ่มในงานเดียวกัน
- ครั้งแรกที่ศัพท์ปรากฏในบท ให้เขียนเป็น `[[term-id]]` ครั้งต่อไปใช้คำไทยได้เลย
- ชื่อคำสั่ง ฟังก์ชัน ตัวแปร และชื่อคอลัมน์ ให้อยู่ใน `backtick` เสมอ

## โครงสร้างบทเรียน
เป้าหมายของบทเขียนไว้ที่ `objectives` ใน frontmatter แอปจะแสดงให้อัตโนมัติ เนื้อหาบทเรียงตามลำดับนี้:
1. `## ทำไมต้องรู้` — 2–4 ประโยคที่เชื่อมเนื้อหากับงาน Data Analyst หรืองานออฟฟิศ
2. หัวข้อเนื้อหา 1–3 หัวข้อ แต่ละหัวข้อมีตัวอย่างที่รันได้อย่างน้อย 1 ชิ้น
3. `## ลองเอง` — ชวนผู้เรียนแก้ตัวอย่างแล้วรันดูผล (ส่วนนี้ไม่ตรวจคำตอบ)
4. `## สรุป` — bullet 3–5 ข้อ
5. แบบฝึกหัดเขียนแยกไว้ใน `exercise.yaml`

## ข้อกำหนดเชิงปริมาณ
- ใช้เวลาเรียน 10–15 นาทีต่อบท รวมแบบฝึกหัด
- เนื้อหาไม่เกินประมาณ 800 คำต่อบท
- มีแนวคิดใหม่ไม่เกิน 3 อย่างต่อบท
- ตัวอย่างโค้ดไม่เกินประมาณ 15 บรรทัดต่อชิ้น
- มีแบบฝึกหัด 1–3 ข้อต่อบท และข้อแรกต้องง่ายเสมอ
- คำใบ้มี 2–3 ขั้นต่อข้อ ขั้นแรกบอกแค่แนวทาง ส่วนขั้นสุดท้ายเกือบเป็นคำตอบ

## กฎสำคัญ
- **ห้ามใช้สิ่งที่ผู้เรียนยังไม่ได้เรียน** ทั้งในตัวอย่าง แบบฝึกหัด และเฉลย ให้ตรวจจาก field `introduces` ของทุกบทก่อนหน้า
- ตัวอย่างที่ติด `run` ต้องรันได้จริง และได้ผลตรงกับที่บทเรียนบอก
- ข้อความใน `assert` ต้องเป็นภาษาไทย บอกว่าผิดตรงไหนและควรลองแก้อย่างไร แต่ห้ามบอกคำตอบตรง ๆ
- ตัวเลขที่อ้างถึงข้อมูลสมมติต้องตรงกับ `content/datasets/README.md`
- ในเนื้อหาหลักให้เขียนคีย์ลัด path และ command line แบบ Windows ส่วนแบบ Mac ให้ใส่ในกล่อง `:::mac`
- ถ้าเนื้อหาเทียบกับ Excel ได้ ให้ใส่กล่อง `:::excel` เพิ่ม
- ชื่อคน ร้าน และสถานที่ในตัวอย่างต้องเป็นของสมมติ และใช้ธีมร้าน "บ้านกาแฟ"
- ในโค้ดและข้อมูลให้ใช้ปี ค.ศ. ยกเว้นบทที่สอนแปลงปี พ.ศ.

## Syntax พิเศษใน lesson.md
| เขียนแบบนี้ | แอปแสดงเป็น |
|---|---|
| code block ภาษา `python run` | โค้ดที่ผู้เรียนแก้และกดรันได้ |
| code block ภาษา `python run error` | โค้ดที่ตั้งใจให้เกิด error เพื่อใช้สอน |
| code block ภาษา `python` | โค้ดที่แสดงอย่างเดียว รันไม่ได้ |
| code block ภาษา `sql run` | SQL ที่รันกับฐานข้อมูลบ้านกาแฟได้ |
| `:::tip` ... `:::` | กล่องเคล็ดลับ |
| `:::warning` ... `:::` | กล่องข้อควรระวัง |
| `:::note` ... `:::` | กล่องข้อมูลเพิ่มเติม |
| `:::mac` ... `:::` | กล่องสำหรับผู้ใช้ Mac |
| `:::excel` ... `:::` | กล่อง "ถ้าคุณใช้ Excel เป็น" |
| `[[term-id]]` | ศัพท์ไทยพร้อมคำอังกฤษ และ tooltip อธิบายความหมาย |
